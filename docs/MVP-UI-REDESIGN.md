# Momentum MVP UI Direction

## Founder decision
Momentum is being reduced from a broad event operating system into a focused relationship-intelligence MVP.

## Primary job
After an event, help a person remember who mattered, understand why, and take the right next action before the relationship goes cold.

## Primary navigation
- Home: relationship queue, progress, next actions
- People: captured relationships
- Capture: fast person/context capture
- Follow-ups: execute and record outcomes

Everything else is secondary and should not compete with this loop in the primary navigation.

## Home hierarchy
1. Event/context
2. Relationship progression metrics
3. Core-loop prompt
4. Relationship queue
5. One-tap capture

## Copy rules
Avoid internal/technical language such as "Universal Event OS", "Pro Suite", "Event Intelligence Suite", and "Networking Objective" in the primary user experience.
Prefer plain language: "People", "Needs action", "Progressions", "Capture someone", "Relationship queue".

## Visual rules
- Dark-first, quiet interface.
- Amber is the primary action accent.
- Reduce gradients, decorative charts, gamification chrome, and competing cards.
- One primary action per screen.
- Preserve accessible focus states and reduced-motion behavior.
- Mobile remains first-class.

## Product success
The UI is successful when a user can answer three questions immediately:
1. Who should I contact?
2. Why should I contact them?
3. What should I do next?

## Core KPI
Meaningful Relationship Progressions / Active User / Event.
